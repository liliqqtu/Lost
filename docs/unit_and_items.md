# 单位、物品与角色成长系统

---

## 一、单位（Unit）数据模型

### 编辑器检查器说明

导出字段上方的 `##` 是 Godot 文档注释：把鼠标停在检查器的属性名上，可查看中文说明。`@export_group` / `@export_subgroup` 提供中文折叠分组；属性英文名仍保持原样，以兼容已有场景、资源和存档。

`Unit` 按身份与阵营、等级与基础能力、装备与个人技能、武器等级上限、当前武器熟练度、对话与战斗演出、运行状态与预留字段分组。常用缩写如下：

| 字段 | 中文含义 | 主要用途 |
| --- | --- | --- |
| `str` | 力量 | 物理攻击力 |
| `mag` | 魔力 | 魔法攻击力、治疗量 |
| `skl` | 技术 | 命中、必杀 |
| `spd` | 速度 | 攻速、回避、追击 |
| `def_h` | 守备 | 抵消物理伤害 |
| `res` | 魔防 | 抵消魔法伤害 |
| `luk` | 幸运 | 命中、回避、必杀回避 |
| `con` | 体格 | 武器重量惩罚、救援判定 |
| `move` | 移动力 | 可消耗的地形移动点 |

这些都是基础值，装备和技能修正另行计算。初始能力在 `Unit` 中配置，升级成长率与上限在 `ClassData` 中配置。`rank_*` 配置可成长的武器等级上限，当前等级由 `weapon_xp` 决定，二者不要混用。

预留字段已在各自提示中标明当前限制：`Unit.status` 尚无异常状态结算，`Unit.cmd` 仅显示指挥星数，`Skill.aura_targets` 尚未控制光环目标筛选。不要仅凭字段存在就假定对应效果已经实现。

每个在战场上可行动的实体（玩家、友军、敌人）均为一个 `Unit` 实例，核心数据结构包括：

1. **八项能力与体格**：
   - 基础值：`str, mag, skl, spd, luk, def_h, res, move, con, hp, max_hp`。
   - 综合有效值查询统一走 `get_effective_*` 接口（自动计算装备额外加成及光环加成，如 `get_effective_skl()`、`get_effective_def(all_units)`）。
2. **职业数据 (`ClassData`)**：
   - 承载职业名、职业卡、能力上限（`cap_*`）、职业成长率、移动消耗表与骑乘类型（步行 / 骑乘·男 / 骑乘·女）。
3. **救援力 (Aid)**：
   - 步行：$\text{Aid} = \text{体格} - 1$
   - 骑乘·男：$\text{Aid} = 25 - \text{体格}$
   - 骑乘·女：$\text{Aid} = 20 - \text{体格}$

## 二、物品与背包生命周期（关键架构约定）

为防止多人开发/AI维护过程中出现“耐久状态不同步”、“已坏武器仍装备”等典型缺陷，严格规定以下生命周期不变量：

```text
[外部系统: 关卡掉落/开箱/交换/运输队/换装]
                 │
                 ▼ 唯一调用入口（严禁直接操作 inventory 数组）
┌────────────────────────────────────────────────────────┐
│ Unit 物品生命周期统一接口：                             │
│ • add_item(item: Item) -> bool                         │
│ • remove_item(item: Item) -> bool                      │
│ • remove_item_at(index: int) -> Item                   │
│ • equip_item(weapon: Weapon) -> bool                   │
│ • consume_weapon_durability(amount: int) -> bool       │
│ • break_current_weapon() -> void                       │
└────────────────────────────────────────────────────────┘
```

### 核心不变量原则：
1. **背包实例唯一性**：`current_weapon` 必须指向 `inventory` 数组内的某个具体实例，严禁脱离背包单独实例化武器。
2. **模板隔离**：所有从 `.tres` 读取的物品，放入背包前必须执行 `duplicate()`，避免多个单位共享同一模板造成耐久互相污染。
3. **损坏自卸装**：武器耐久降至 0 时，自动触发 `break_current_weapon()`，同时卸下装备并从背包中销毁。
4. **背包上限**：常量 `Unit.BAG_LIMIT = 5`。

## 三、武器等级与熟练度（Weapon Rank）

武器熟练度定义在 `scripts/weapon.gd` 中，阈值遵循 FE8 原版标准：

| 等级 | 所需武器经验 (WEXP) | 说明 |
| :---: | :---: | :--- |
| **E** | 1 | 基础入门武器（铁系武器） |
| **D** | 31 | 进阶武器（钢系武器、投枪） |
| **C** | 71 | 特殊效果武器（破甲剑、必杀剑、勇者武器） |
| **B** | 121 | 高级武器（银系武器） |
| **A** | 181 | 顶级武器 |
| **S** | 251 | 专属神器（如断弦，附带特技与高额属性增益） |

- **数据归属**：`rank_*` 归属于 `Unit`，表示该单位各武器类型的可用性与**等级上限**；`weapon_xp` 字典存储各类型累计经验。
- **初始熟练度**：未配置 `weapon_xp` 的可用类型从 E 阈值 1 开始；角色场景显式配置初始经验，保留现有角色的开局等级。`rank_*` 只限制上限，不再把首次查询直接初始化到上限。
- **装备判定**：`can_equip()` 校验单位当前的有效等级（`get_weapon_ex`）是否满足武器的 `required_rank`。

### FE8 原版物品目录与商店元数据

- 原版独立模板存放于 `data/items/fe8/`；图标按 `docs/assets.md` 的八种武器与杂物目录归档。具体清单、原版数据来源与效果接入状态见 `docs/fe8_item_catalog.md`。
- `Item.buy_price` 为满次数买入总价；`0` 表示未定价或禁止交易。`can_sell` 控制能否出售。`item_kind` 为道具细分类；运输队武器类别仍统一读取 `Weapon.weapon_type`。
- 原始使用次数保存在普通 `Item.remaining_uses/max_uses`，武器与已支持消耗品继续使用 `durability/max_durability`。通用物品行统一显示对应次数。
- `effect_id`、`effect_implemented` 与 `original_data` 登记原版效果及待实现边界，不自动执行效果。未实现道具保留为普通 `Item`，避免误入伤药流程；新特殊法杖未实现时不可进入治疗指令。未填写效果 ID 的旧治疗杖保持原行为。
- 商店购买从模板 `duplicate(true)` 生成独立物品，再调用 `Unit.add_item()` 或 `ConvoyStore.add()`。出售调用 `Unit.remove_item()`，同步卸下被售出的装备。

### 共用资金与存档

`SaveManager.party_funds` 是 `{ "gold": int }` 钱包。商店默认使用此对象，测试可注入独立字典。金币通过战役快照的 `gold` 字段保存、加载并带入下一章；旧存档缺少该字段时为 0，新游戏重置为 0。交易本身不立即写入磁盘，仍遵循原有存档流程。

## 四、支援系统（Support System）

采用 FE8 属性加成与定制的章节出战积累机制：
1. **积累规则**：我方胜利结算时，双方均登场出战的支援对自动增加 1 点支援值（上限达 A 级门槛）。
2. **升级触发**：达到门槛后，行动菜单在相邻时动态显示“支援”选项，播放对话后正式升阶。
3. **加成结算**：曼哈顿距离 $\le 3$ 格生效，根据双方属性（炎/暗/理/雷/冰/光/风）贡献度之和乘以支援等级倍率（C:1x, B:2x, A:3x）。
